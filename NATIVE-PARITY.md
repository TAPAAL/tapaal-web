# Native behaviour coverage and replacement plan

Research audit, 2026-10-28. Native checkout HEAD: `28c9bd9174c052264db8af7a02a214dd1c37d4c4`.

At the audit baseline the web app was an untimed, uncolored, single-component editor and simulator. The integration notes below describe subsequent progress; it is not yet a complete native replacement. The next investment should be modelling speed, document safety, and semantic fidelity. A toolbar, dialog, or screenshot resemblance does not establish that its workflow works.

## Integration progress (after this audit)

### Remaining gaps after the 2026-11-01 iteration

- **Model families:** coloured types/expressions/token bindings and stochastic simulation remain unsupported. Uncoloured timed/untimed games support manual exploration, not strategy synthesis or adversarial scheduling.
- **Analysis:** queries are preserved, but query editing, verification engines, results and imported verification traces are not implemented.
- **Transfer:** shared/game subnet clipboard and native timed/symbolic clipboard interchange remain gated. Component copies preserve supported roles and memberships.
- **Native examples:** 19 of 29 originals open; ERK's duplicate arc ID A43 is refused, and coloured/stochastic families account for the other nine gates. Originals are never altered to gain support.
- **Layout:** arc offsets persist exactly, but native Swing label anchoring/font metrics/grid-aligned painting and native Smart Draw layout are not reproduced.
- **Native file compatibility:** released TAPAAL 4.0.4 drops nonzero initial token ages. The web warns and preserves them in JSON; this cannot be fixed by changing the web writer alone.

## Evidence and scope

This is a source audit, not an executed parity test. Native handlers, controllers, dialogs, serialization, and selected engine integration paths were inspected. No application code was changed; no builds, tests, servers, commits, PRs, or deployments were run. Existing uncommitted work was preserved.

The shared `web/` tree was changing during the audit. **W0** below means the initial source read: `app.ts` had six tools, unconditional wheel zoom, fixed 20-unit snapping, one `NetEditor`, and one `Simulation`. **W1** means later in-flight source observed: navigation/grid changes were present in `app.ts` around lines 606–620 and 804–862. W1 was read only to avoid reporting already-in-progress work as wholly absent; it was not tested or certified. Web line numbers can move during integration. The parent must reconcile these rows with the final implementation and its tests.

Evidence labels:

- **I**: implementation/control flow inspected; this does not mean runtime verified.
- **S**: surface or wiring inspected (actions, fields, call sites); detailed implementation/semantics remain to be audited.
- **R**: recommended browser behaviour or workflow inference, not a claim about observed users or native implementation.
- **U**: explicitly uninspected detail. No parity credit should be awarded from U.

“Experienced workflow” here is inferred from the native commands and interactions, not user interviews or telemetry. Every listed acceptance scenario is a proposed test, not a passing test result.

Priority: **P0** blocks dependable everyday modelling or risks losing work; **P1** is required for broader native replacement after that foundation; **P2** is specialist/secondary integration. P1/P2 does not mean dispensable. For a timed, colored, game, or stochastic user, the relevant semantic and engine rows become blockers before claiming replacement for that user.

Implementation route: **B** = browser UI/model/serialization is feasible without a native process; **B+S** = browser feasible but needs a substantive, validated semantic implementation; **E** = existing native workflow depends on verification/interactive engines, requiring a service/local companion or a separately proven port. These are architecture judgments, not claims that a browser port already exists.

## What the source evidence changes about implementation order

1. **Use a document/network model before expanding the property panels.** Stable document, component, local-node, shared-entity, query and declaration IDs must outlive display names. Geometry (including labels, points, angles, notes) belongs in persistent data. Viewport/selection/tool previews belong in view/session state. A boolean “timed” on the existing flat `Net` is not sufficient.
2. **Treat actions as complete transactions.** Node+arc creation, quick-draw continuation, transport pair creation, subnet paste, dialog commit, cascade delete, and group movement need defined commit/cancel/undo boundaries. Native code is a reference, including limitations; do not reproduce apparent bugs solely for matching.
3. **Make file support a contract.** For each lens/feature, state editable/preserved-only/rejected/conversion-required. An opaque unknown XML subtree is not automatically safe to retain after renaming referenced entities; either update its references with proven rules or prevent conflicting edits. Never label a lossy subset export as a full native save.
4. **Separate simulation from verification.** Browser untimed marking execution can remain local. Timed simulation needs a deliberately tested semantics layer. Native colored simulation already uses an interactive engine. Query execution, unfolding, game solving, and SMC need explicit backend contracts, not a “Verify” button returning guessed answers.
5. **Use engine capability discovery and immutable requests.** Recommended service/companion boundary: model revision/hash + lens + serialized document + query AST/options + engine/version → job ID, progress, cancellation, structured outcome, raw output, stats, mapped trace. Interactive simulation additionally needs session/reset/bindings/fire/close semantics. This boundary is **R**, not implemented in this audit. Whether to host engines remotely or locally is a product/deployment choice; neither is implicitly authorized here.

## Validation corpus and uninspected edges

Recommended fixtures (**R**): minimal untimed self-loop with weighted arcs; inhibitor boundary; disconnected net with bends/curves/notes/rotated transition; duplicate local names across two components; shared places and synchronized transitions; inactive component referenced by query; symbolic constants and rename/delete dependencies; timed strict/open bounds with urgent transitions and nonzero initial ages; transport destination invariant; colored binding ambiguity/product colors; game controllability; stochastic distributions and SMC observations; standard PNML separate from TAPAAL dialect; imported engine trace with composed-name mapping. For each, compare graph/semantics/geometry, perform an edit, undo/redo, save, reopen in native, and replay expected behaviour.

Coverage of all feature families is not exhaustive proof of every dialog field or algorithm. Specifically uninspected or only surface-inspected:

- Exact platform/Look-and-Feel Shift-wheel horizontal scrolling; object-wheel modifier precedence at runtime, trackpads and browser gesture interaction.
- Complete automatic-layout worker scoring/cancellation behaviour and precise bounds fitting for every graphic object.
- Every color expression/type editor, game synthesis semantics, stochastic distribution parameter rule, custom distribution editor, observation graph/export option, and all engine-feature matrices.
- Full delete/rename impact propagation, clipboard handling of every advanced field, template-copy sharing semantics, annotation resize details, and maximum undo-buffer policy.
- Full PNML/query/trace grammar compatibility, legacy file migrations, native load diagnostics, exact round-trip preservation of unknown XML metadata and label visibility/rotation.
- Actual native/runtime engine binaries, protocol/version compatibility, service hosting/companion packaging, browser file/clipboard permissions, and performance on very large models.
- End-to-end accessibility, keyboard layout/platform differences, responsive layouts and touch interactions. Existing web focus/menu support was seen, but no assistive-technology testing was performed.

Resolve these with targeted source inspection and behavioural tests as the relevant wave lands. Do not expand scope by claiming the missing semantics are “just UI”.
